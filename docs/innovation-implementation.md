# 主动诊断与效果核验：实施说明

2026-09-20。对应已批准方案 I1—I4；I5 水费试算仍属二期。本次交付为可运行的模拟诊断、有限复测、工单效果核验与实验对照流程。**功能测试与模型效果分开验收：模型效果门槛未通过，诊断默认关闭。**

## 已接入的流程

1. 管理员进入“诊断中心”，选择明确的水表范围与关闭/影子/辅助诊断模式。保存时校验策略版本，避免覆盖其他管理员的更新。
2. “模拟诊断输入”接收七字段报文。结构化观测、请求审计、独立累计读数游标与分析任务一起保存；诊断输入不新增正式抄表、账单或支付流水。正常采集也可留下诊断观测，但仍由原正式计费游标结算。
3. 个体基线按工作日/周末与四小时时段分组，使用过去28天、至少14个有效日及200个区间，每组至少8条历史。当前三个窗口不参与自身基线。缺失不补零；三段连续偏高、设备报警、温度或关阀流量异常均保留原因码与快照。
4. 影子模式只保存候选及证据。辅助模式可记录正式异常；持续用水偏离安排5/15/30分钟三次复测，每次最多再试一次，单表每日最多24次额外请求，全局最多10个在途请求。任务有持久化租约、预算、取消原因与幂等请求号。
5. 复测结束后交由人工判断。管理员可追加“确认异常/正常经营/设备故障/证据不足”标签，并明确确认创建工单。不会自动关闭阀门、改价或扣费。
6. 关联工单完成后建立独立核验记录。至少观察24小时，15分钟格覆盖率至少90%、最长空档不超过30分钟；最长72小时后证据仍不足则显示“无法判断”。异常持续时可明确确认创建新的关联复检工单，原工单和原处置结果保留。
7. 消息中心新增诊断进度；普通连续观测不刷新未读版本，处置/核验状态变化会更新。用户仅能查看当前仍归属自己的辅助诊断简要进度，无法访问管理员证据、策略或演练。
8. 智能助手支持“诊断事件 #123 的依据”“诊断事件 #123 的复测进度”“工单 #123 的核验结果”，返回查到的记录和页面入口，不执行处置。

## 模拟与实际边界

- 当前主动复测为**恒流模拟采集器**，从固定起点按经过时间积分；多请求不会凭空多用水。没有接入真实设备通信。三次模拟成功也不会自动宣告现场正常，仍须人工核查。
- 学习模型是实际训练的 Isolation Forest，使用固定特征顺序、依赖版本和种子；评分仅是异常排序分数，不是漏水概率。默认不加载在线模型；缺少历史或模型不可用时使用基础规则并显示原因。
- 核验保存基线/策略快照。设备问题按基础规则检查；用水问题按对应工作日/周末、四小时时段的冻结基线，比较累计量差形成的区间流量。缺少全天分组的旧快照不能证明恢复。同一采样格内较早的硬报警不会被后续正常报文覆盖。它证明观测条件下的恢复，不等于现场维修证明；换表、停表、归属变化、关阀低流量和缺失观测不能冒充恢复。
- 演练服务在本地8088端口使用独立文件，不连接任何业务数据库。Java通过受保护接口转发管理员请求。原方案拟定独立MySQL/8081，实施选择了更小的文件隔离方案，避免第二套业务服务及实验误写账务。
- 演练生成分钟级轨迹，15分钟采样，支持暂停/继续及推进一个处理检查点；检查点为模拟表日，不是假装真实设备逐报文运行。进程重启后未完成演练明确标记“服务中断”，需按原种子重建；已完成报告可再次查看。
- 基线版本快照存在证据表，模型与清单在受控本地目录；当前没有独立在线模型注册中心或自动训练发布功能。人工标签只追加留痕，不自动训练。

## 实验结果与失败类别

每组60块表、84天，种子20260920/20260921/20260922；时间切分为前56天训练、14天验证、最后14天测试。各类型分别留出约20%的水表，留出表不用于训练/阈值选择。阈值由验证集确定；测试标签只参与指标计算。原始报文不含真值标签。

场景覆盖居民峰值、夜间经营、小流量持续、高流量、通信缺失、报文质量、临时增量，以及恢复/持续/缺数据的维修后轨迹。A使用现有10m³/h设备硬规则；B加入个体基线；C在B上加入候选模型。三组共享质量校验。

| 种子 | A 检出/误报/漏检 | B 检出/误报/漏检 | C 检出/误报/漏检 |
|---|---|---|---|
| 20260920 | 47 / 0 / 68 | 81 / 159 / 34 | 81 / 159 / 34 |
| 20260921 | 47 / 0 / 68 | 79 / 156 / 36 | 79 / 156 / 36 |
| 20260922 | 47 / 0 / 68 | 79 / 158 / 36 | 79 / 158 / 36 |

A召回率40.9%，B/C为68.7%—70.4%。B增加了检出，也增加了误报；C未取得额外收益。**不能宣称“误报下降20%且召回下降不超过2个百分点”达标。** A的误报基数为0，下降比例也不可计算。当前建议保持关闭，先用影子范围验证和核查误报，不进入自动处置。

通信缺失主要表现为弃权，当前检测器没有独立“离线事件”生成机制；低强度事件也存在漏检。各类样本少于30时报告标记不足，不给出可靠性保证。分类型只统计检出/漏检与延迟，不能把无法归属类型的误报删掉后宣称精确率高。漏检不作为零延迟；报告保留漏检事件ID。

首次探索报告 `logs/innovation/evaluation-20260920.json` 使用0.1m³/h对照且留出类型不均，仅留存供审计；正式v2恢复现有设备阈值并按类型留出，未继续用测试集调参。模型效果与人工复测成本尚无真实设备标注数据支持。

正式报告为 `logs/innovation/evaluation-v2-20260920.json` 至 `20260922.json`，可从创新演练页面下载。摘要与模型/报告SHA256清单在 `output/innovation/evaluation-summary.json`；完整轨迹由固定种子重建。模型文件在 `logs/innovation/models/`，不提交训练依赖或模型二进制到Git。

## 启动与复现

常规服务使用 `tools/start-local.ps1`，会按顺序应用增量迁移；新增迁移是 `database/migrations/20260920_innovation.sql`，默认策略off且范围为空。初始化SQL也包含新表。更新运行中的Java前需停止本项目对应进程再打包，避免Windows占用JAR。

在项目根目录执行：

```powershell
# 可选实验依赖隔离安装，不覆盖现有智能引擎的NumPy环境
& ./.venv-local/Scripts/python.exe -m pip install --target logs/innovation/deps -r agent-engine/requirements-innovation.txt
& ./tools/start-innovation-lab.ps1
& ./tools/test-innovation.ps1
# 完整三组实验耗时更长，显式选择
& ./tools/test-innovation.ps1 -RunExperiments
& ./.venv-local/Scripts/python.exe tools/innovation-report.py
& ./.venv-local/Scripts/python.exe tools/benchmark-innovation.py
```

依赖锁定为NumPy2.2.6、SciPy1.15.3、scikit-learn1.7.2、joblib1.5.2、threadpoolctl3.6.0。离线模块主动加载独立目录。线上仍可只用规则；如将来加载模型，须使用匹配依赖与受控 `INNOVATION_MODEL_VERSION`，不能接受浏览器传入任意模型文件路径。

管理员入口 `http://127.0.0.1:3000/diagnosis` 与 `/lab/replay`；原管理员admin/admin123可用。8087/8088的内部业务接口都要求同一内部密钥，启动脚本只从忽略提交的密钥文件读取。演练健康检查为 `http://127.0.0.1:8088/api/health`。

## 性能测量的适用范围

最终隔离MySQL测试库一次导入1000块表、每表96条15分钟采样，共96,000条观测，导入约1.04秒。10并发、共200次事件列表服务调用P95约15.83毫秒。该测试绕过HTTP与浏览器，不能直接称为10并发用户端到端性能。

Python使用每表1537条完整历史，5批、每批100次特征/基线计算加一次真实模型批量评分，P95约1.56秒，低于2秒组件目标；不含网络与数据库时间，不是100次HTTP逐一模型推理的成绩。

日志 `logs/innovation/performance-java.json`、`performance-python.json` 保留样本数量、持续时间、范围与结果。1000表仅验证本机加速导入和列表组件，不换算成生产设备容量。

## 5—8分钟演示顺序

1. 演练页查看三组完整报告，解释场景、对照口径、漏检与未达标结论（1分钟）。
2. 诊断中心选择专用演示水表，先影子后辅助；提交报文，查看原始观测、个体基线/冷启动及原因（2分钟）。
3. 用准备好的连续历史演示复测任务时间、预算、重试/取消；说明恒流模拟限制（1分钟）。
4. 明确确认创建工单，接单并写处置结论；查看独立核验卡，展示三类结果的测试样例（1分钟）。
5. 用户端查看本人进度、消息直达；助手按事件编号给出证据入口（1分钟）。
6. 恢复诊断关闭，清理仅属于本次演示的专用记录。真实24小时观察不可用短暂演示冒充，已验证的固定时钟测试用于展示判定边界。

测试证据、T01—T16对应关系及最终验证次数见 `docs/innovation-acceptance.md`。
