# 计费与缴费流程完善设计

日期：2026-09-17。状态：用户已确认范围，计费缴费基础已实现并验收；后续阶段见赛题清单。

## 目标与范围

先修复费用计算和收款记录的准确性，再完成管理员缴费页面，使账单查询、缴费登记、欠费更新和凭据查看形成可验收流程。遵循 [赛题对照清单](../../competition-requirements.md)，本轮对应 R2 的基础与管理员收费模块，不宣称已完成用户端、权限、真实支付网关、自动调度及报表。

继续沿用现有 Vue、Spring Boot、MyBatis-Plus 和 MySQL，保留已有启动修复和管理员账号 `admin / admin123`。

## 方案选择

1. **先完成计费缴费（推荐）**：消除零金额出账和错误结清问题，后续用户端及自动采集可复用可靠账务服务。优点是解决现有核心数据错误；权限与用户端作为下一阶段。
2. **先完成权限和用户端**：先实现赛题明确要求的角色隔离，但用户端收费仍依赖修复现有账务错误，首个交付涉及更多模块。
3. **先完成采集调度和报表**：便于展示智能体流程，但在账务未修复时自动化可能放大错误数据，因此不作为首选。

## 账单生成

- 只允许存在、未删除、审核通过的抄表生成账单，水表 ID 和用户归属必须一致。
- 使用抄表记录中采集时保存的 `usageAmount`；要求非空且不小于零。终止读数取 `readingValue`，起始读数为终止读数减用量；不使用已被后续采集更新的水表当前值推算历史账单。
- 居民、商业、工业费率沿用现有配置，金额以 BigDecimal 计算，最终保留两位小数；非法用户类型明确报错。
- 同一有效抄表记录只允许一张有效账单；生成时在事务内锁定对应抄表行，再检查已有有效账单，防止本服务并发重复生成；重复请求返回既有账单。
- 账期优先使用抄表账期，缺失时取抄表发生月；初始已付和违约金为零，保存可解析的费用明细 JSON。
- 批量生成逐项报告已创建、已存在、失败；业务失败不计为成功。

## 缴费登记

- 当前阶段提供本地演示/线下收款登记，不把选择“微信/支付宝”视为已经调用真实支付机构。前端明确展示登记性质，后续支付网关回调复用账务服务。
- 支持部分缴费和结清剩余欠款；金额必须为正、最多两位小数且不超过剩余应付。无效账单、渠道或数据不写库。
- 已付金额累加，剩余金额以服务端计算为准；部分缴费保持部分支付状态，结清才变为已支付。逾期查询包含所有仍有欠款的有效账单。
- 增加缴费流水表，记录账单、金额、方式、登记时间、交易/请求唯一标识；账单更新与流水写入放在同一事务，锁定对应账单行。
- 同一请求标识、相同账单金额渠道重复提交返回原流水；相同标识但内容不同拒绝。两个并发请求不能造成超收、丢失更新或重复入账。
- 不直接扣用户余额；余额账户和真实网关属于后续独立功能。

## 页面与接口

- `Payment.vue`：按账单号、用户名、账期、状态查询，展示账单金额、累计已付、剩余应付、状态；支持分页及加载、空列表、失败重试提示。
- 收款对话框展示账单详情、剩余金额、渠道及本次金额；提交期间禁止重复点击，成功后刷新账单与汇总。失败保留输入并显示实际错误。
- `bill/List.vue` 复用同一缴费组件，避免两个入口逻辑不同；详情按钮打开真实账单详情和缴费流水。尚未对接的催缴功能不再显示“已发送”。
- 后端保留现有账单列表入口，扩展真实流水查询和缴费返回；按现有统一成功/失败结构返回，前端不得把 HTTP 200 中的业务失败当成成功。

## 数据迁移和运行方式

- 新增独立、可重复执行的数据库迁移脚本，不重建原表或清空已有演示数据；新库初始化脚本同步新增结构。
- 对历史已支付账单不伪造支付流水；界面可以显示已付汇总并注明没有历史流水。
- 部署前检查同一抄表是否已有多张有效账单；发现冲突应列出并停止启用新出账流程，不自动删除财务记录。
- 业务修改后重建后端并仅重启本项目进程，前端仍使用现有 Vite 端口；更新启动说明中的迁移步骤与功能完成状态。

## 验收与回归

1. 读数 150、用量 30 时账单起止为 120/150、用量 30，按配置得到非零费用；覆盖阶梯临界值、商业/工业类型。
2. 拒绝跨水表、未审核、负用量和缺失记录；同一抄表重复及并发出账不产生重复账单。
3. 100 元账单先登记 40 元，状态部分支付、欠款 60；再登记 60 元后结清，两笔流水合计 100。
4. 负数、零、三位小数、超额、无效渠道、对已结清账单继续缴费均失败，账单和流水均不变。
5. 同一请求重试不重复计入；并发收款正确串行校验剩余金额，失败事务回滚。
6. 页面真实查询、部分支付、结清、详情和流水可操作；两处缴费入口行为一致，失败不会误显示成功。
7. Maven 账务测试和接口检查通过，前端构建通过；保留数据的迁移可重复运行。记录验证命令和结果。
