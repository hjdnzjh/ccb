# 水务助手回答修复设计

## 已证实的问题

OpsServiceImpl.assistant 把问题传入 period，并调用 AnalysisAgent 的随机模拟报表。HTTP 成功即认为回答有效，随后把 Map.toString 暴露给用户；context 不参与真实业务查询。无意图、范围、证据及数据不足处理，界面也没有具体对象和操作入口。

## 方案与范围

单纯格式化仍会展示假数据；直接增加语言模型不能解决数据可信问题，且当前没有已配置的模型接入。因此先修复现有模块为可验证的业务问答：独立 AssistantService + 只读 AssistantRepository，沿用管理员权限和现有接口，移除该接口的模拟报表调用。页面标明基于业务数据和规则分析，不宣称通用大模型或预测模型。

- 巡检：当前未删除且在役/故障水表，按故障、未处理告警、电量、信号、上传间隔列出前十名及具体依据；未知值不可视为正常，停用/更换不混入。
- 漏水：按指定区域（名称、编码或现有 A区/B区别名）及下级区域过滤，列出未处理夜间用水/突增/漏水记录；只说明疑似风险，不能认定已漏水。未知区域、多区域须澄清，不能偷偷改成全局。
- 收入：本月至当前时刻与上月同期比较，采用 bill_payment 实际登记流水，不把 bill.paid_amount 当月度收款；零基数不算百分比，流水缺失不能断言收入下降，更不能推断原因。只提供本月口径，其他日期请求引导统计报表。
- 欠费：查询当前未结清账单余额，包含部分付款；列出欠费笔数与应收余额。区域/单表限定不支持时明确解释，禁止忽略筛选条件。
- 非支持问题、多个主题、模糊追问：返回能力边界及具体示例，不生成无关统计；所有请求只读，不直接派单、调价或扣费。

响应包含结论、证据列表、指标、巡检表格、数据来源/时间/范围、限制与固定业务链接。前端安全文本渲染，不显示内部变量和服务名；中文输入法 Enter 不误提交，限制长度、处理中禁用重复发送，支持清空会话及失败重试。

## 验证

单元测试覆盖意图、无数据、区域与单表、未支持日期、排序原因、零基数、不接受下降前提。MySQL 独立测试库验证区域隔离/已关闭排除/聚合不重复/部分付款与流水边界。浏览器使用截图原问题验证具体表号、重复请求稳定、无 Map 原文，验证区域漏水、收入、无关问题和界面交互。更新 README，构建后重启本项目后端并复验。
