# 消息中心实施与验收

需求：修复首页铃铛点击无反应并扩展为站内业务提醒。
根因：Layout 的铃铛跳回 dashboard，角标来自 cockpit.signals，没有消息或已读模型。

采用业务实时派生的消息抽屉，复用现有业务处理页面；无需单独事件队列。相较只增加跳转，此方案具备独立阅读状态；相较全量事件收件箱，避免补造历史通知和重复存储业务数据。

- 管理员：未处理异常、未完成工单、七天内到期的欠费账单、失败采集、未解决反馈。
- 用户：自己的七天内到期欠费账单、最近反馈回复。服务端根据会话决定数据范围。
- 每类最多 100 条，按业务时间倒序。明确展示当前范围和截断提示；角标仅代表当前范围未读数，不声称历史全量消息。
- 已读表以用户 ID + 消息内容版本摘要为主键。状态或内容变更形成新版本；已结清/已处理的待办退出当前消息列表。反馈回复保留最近记录。
- 标记已读/未读校验当前账号可见的消息键；批量已读只提交点击时当前筛选范围的消息键，避免并发新消息被误标。无推送短信/邮件副作用。
- 抽屉提供分类、未读筛选、搜索、分页、消息详情、业务入口、账单详情、刷新、空态/错误重试；60 秒可见页面刷新，卸载取消监听。

实施顺序：后端 MySQL 集成测试 → 数据迁移与鉴权接口 → 抽屉和铃铛 → 构建和浏览器验证 → README。
验收重点：普通账号数据隔离、多人已读独立、内容更新再次未读、批量操作不影响新消息、已读不改变业务状态、首页点击打开抽屉、刷新后状态保留、加载失败可恢复。


完成记录（2026-09-20）：迁移、账号隔离接口、消息抽屉、详情定位和文档均已落实。98项Java测试及9项前端测试通过，浏览器验收覆盖桌面/手机、错误恢复与权限；复现并修复侧栏遮挡和账单弹层覆盖。具体证据见README第14节。
